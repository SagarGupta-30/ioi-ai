# MongoDB Integration

## Why MongoDB

MongoDB is used as the primary document database for IOI AI because:

1. **Document structure matches our data** — student records have nested objects (projects, publicLinks, source metadata) that map naturally to MongoDB documents rather than relational tables.
2. **Schema flexibility** — real PW IOI records are sparse (only name, gender) while synthetic records have rich fields. MongoDB handles this variation without empty columns.
3. **Mongoose ODM** — provides schema validation, TypeScript integration, and a clean query API on top of MongoDB.

## Database Details

| Setting | Value |
|---------|-------|
| Database name | `ioi_ai` |
| Student collection | `students` |
| ODM | Mongoose |

## Student Document Structure

Each document in the `students` collection follows the normalized Student schema:

```json
{
  "_id": "ObjectId (auto-generated by MongoDB)",
  "id": "119e4b7e-7052-4acd-844b-c1ac49a67824",
  "name": "Aarushi Mandloi",
  "campus": "Bengaluru",
  "batch": "24",
  "gender": "FEMALE",
  "address": null,
  "school": "SOT",
  "skills": [],
  "projects": [],
  "interests": [],
  "publicLinks": {
    "linkedin": null,
    "github": null,
    "portfolio": null
  },
  "source": {
    "type": "pwioi_public_api",
    "status": "public",
    "origin": "https://api.pwioi.club/...",
    "ingestedAt": "2026-09-28T15:40:00.000Z"
  },
  "createdAt": "2026-09-29T...",
  "updatedAt": "2026-09-29T..."
}
```

### Key fields

| Field | Required | Notes |
|-------|----------|-------|
| `id` | Yes | Stable UUID from PW IOI API or generated for synthetic records. Unique index. |
| `_id` | Auto | MongoDB's internal ObjectId. Not used as the primary business identifier. |
| `name` | Yes | Full name |
| `campus` | Yes | Campus location |
| `batch` | Yes | Graduation year |
| `gender` | Yes | `"MALE"` or `"FEMALE"` |
| `school` | Yes | School code (currently always `"SOT"`) |
| `source` | Yes | Provenance metadata — type, status, origin, ingestedAt |
| `skills` | No | Empty array for real records |
| `projects` | No | Empty array for real records |
| `interests` | No | Empty array for real records |

## Mongoose's Role

Mongoose sits between the Express backend and MongoDB:

```
Express routes  →  Mongoose Model  →  MongoDB
```

It provides:
- **Schema validation** — ensures required fields are present and enums are respected
- **TypeScript types** — `StudentDocument` extends our `Student` interface
- **Query API** — `StudentModel.find()`, `.updateOne()`, etc.
- **Middleware hooks** — timestamps, transforms

The Mongoose model is defined in `backend/src/models/student.model.ts` and reuses the TypeScript interfaces from `backend/src/models/student.ts`.

## Environment Configuration

Create a `.env` file in `backend/` (copy from `.env.example`):

```
PORT=5001
MONGODB_URI=mongodb://localhost:27017/ioi_ai
```

The `.env` file is gitignored. Never commit real connection strings.

## Starting MongoDB Locally

### Option 1: Using Homebrew (macOS)

```bash
# Install
brew tap mongodb/brew
brew install mongodb-community

# Start
brew services start mongodb-community

# Verify
mongosh --eval "db.runCommand({ ping: 1 })"
```

### Option 2: Using Docker

```bash
docker run -d --name mongodb -p 27017:27017 mongo:7
```

### Option 3: MongoDB Atlas (cloud)

Create a free cluster at https://cloud.mongodb.com and update `MONGODB_URI` in your `.env` file.

## Running the Seed Script

The seed script inserts the two example student records (one public, one synthetic):

```bash
cd backend
npm run seed
```

Expected output:
```
[ioi-ai-backend] MongoDB connected — database: ioi_ai
[seed] Inserted: Aarushi Mandloi (pwioi_public_api)
[seed] Inserted: Priya Sharma (synthetic)

[seed] Done. Inserted: 2, Skipped: 0
[seed] Total students in database: 2
```

The script is idempotent — running it again will skip existing records.

## MongoDB vs. Future Vector Database

| Aspect | MongoDB | Vector Database (future) |
|--------|---------|--------------------------|
| **Purpose** | Structured student data storage | Semantic similarity search |
| **Data** | Student records (name, campus, skills, etc.) | Text embeddings (numerical vectors) |
| **Queries** | Exact match, filters, aggregation | Nearest-neighbor vector search |
| **When** | Now (Step 4) | Future (RAG pipeline step) |

MongoDB stores the **source of truth** for student records. The vector database will store **derived embeddings** generated from these records for the RAG retrieval pipeline. They serve complementary roles.
